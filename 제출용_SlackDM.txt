1. 프로젝트 주제 및 기획 의도
━━━━━━━━━━━━━━━━━━━━━━━━━━━

*AskDB — 한국어 질문 한 줄로 사내 DB를 조회하는 Text2SQL 시스템*

데이터는 이미 DW에 다 들어 있는데, 정작 숫자가 필요한 사람은 SQL을 쓰지 못합니다.
"지난달 채널별 매출 좀 뽑아주세요"라는 한 줄이 데이터팀 티켓으로 쌓이고 하루 이틀 뒤에
답이 오며, 데이터팀은 반복적인 단순 추출 요청에 시간을 소모합니다.
의사결정 속도가 조직의 SQL 문해력에 묶여 있는 상태입니다.

다만 사내 DB에 LLM을 그냥 연결하면 두 가지가 반드시 터집니다.
 (1) 틀린 숫자를 자신 있게 답한다 — '매출'의 정의가 사람마다 달라 같은 질문에 다른 결과가 나옵니다.
 (2) 위험한 쿼리가 실행된다 — DELETE·DROP이나 DB를 마비시키는 전체 스캔이 그대로 돕니다.

그래서 이 프로젝트는 SQL 생성 자체보다 *"정확도 장치"와 "안전 장치"를 파이프라인으로
명시화*하는 데 초점을 맞췄습니다. 실제 사내 DB로 확장할 때 그대로 이어 쓸 수 있는
구조를 만드는 것이 기획 의도입니다.

2. 주요 기능 및 활용 방법
━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 6단계 파이프라인 (전 과정이 화면에 그대로 추적됩니다)

 ① 스키마 링킹 — 질문과 관련된 테이블만 선별
    (한국어 동의어 사전 + 컬럼 코멘트 유사도 + 실제 값 매칭 + FK 연결성 탐색)
    → 테이블 수천 개인 실제 DW에서 전체 스키마 주입은 불가능. 9테이블에서도 토큰 약 60% 절감
 ② 유사 예제 검색 — 검증된 (질문, SQL) 쌍 중 유사한 4건을 프롬프트에 주입
 ③ SQL 생성 — LLM이 <reasoning> / <sql> / <assumption> 형식으로 분리 출력
    → 판단 근거와 해석 가정을 사람이 검토할 수 있게 만듦
 ④ 정적 검증·가드레일 — sqlglot AST 파싱으로 단일 SELECT 강제,
    DDL/DML·환각 테이블·민감 컬럼 차단, LIMIT 자동 주입 → 실행 '전에' 차단
 ⑤ 읽기전용 실행 — mode=ro 커넥션 + 쿼리 타임아웃 8초 (드라이버 수준 2차 방어)
 ⑥ 자기수정 — 검증·실행 오류를 모델에 되먹여 재생성 (기본 2회)
 ⑦ 사용 컬럼 분석 — 생성된 SQL을 AST로 되짚어 '실제로 읽은 테이블·컬럼'과 그 용도
    (출력/조건/조인/그룹/정렬)를 표로 출력 → 답의 근거를 눈으로 확인 가능

■ 화면 구성 (4개 탭)

 • 질문하기 — 한국어로 질문하면 파이프라인 추적 → 자연어 답변(스트리밍) → 결과 표 →
   자동 차트(시계열은 라인, 범주형은 바) → 생성 SQL → CSV 다운로드 순서로 나옵니다.
   👍 버튼을 누르면 그 질문-SQL 쌍이 예제 뱅크에 축적되어 이후 질문 정확도가 올라갑니다.
   답변 아래에 '이 답의 근거 — 실제로 사용된 테이블·컬럼'이 표로 붙습니다. 컬럼별로
   어느 절에서 쓰였는지까지 보여주고 CSV로 내려받을 수 있습니다.
 • 스키마 탐색 — ERD 관계도를 기본 화면으로 제공합니다. 테이블 성격별 색상(팩트/마스터/독립),
   PK·FK 배지, 1:N 까치발 표기, 자기참조 점선까지 표시하며, 스키마 링킹이 직전 질문에서
   고른 테이블을 ERD 위에 주황색으로 강조합니다. ERD는 스키마에서 자동 생성되므로
   DB가 바뀌면 그림도 자동으로 따라옵니다. 컬럼·코멘트·실제 값 목록·샘플 행,
   '모델에게 주입되는 스키마 원문', 지표 표준 정의도 함께 공개합니다.
 • 자동 평가 — 골든셋 12문항의 실행 정확도(Execution Accuracy)를 버튼 한 번으로 측정.
   문항별로 모델 생성 SQL과 정답 SQL을 나란히 비교하고 리포트를 CSV로 내려받습니다.
 • 프로젝트 설명 — 설계 의도, 안전 설계, 실서비스 확장 로드맵

■ 정확도를 만드는 3가지 설계

 1) 세만틱 레이어 — "매출 = SUM(수량×단가 − 할인) where status='완료'" 처럼 지표를
    프롬프트에 못 박았습니다. 이것이 없으면 같은 질문에 매번 다른 숫자가 나옵니다.
 2) 값 기반 스키마 표현 — 컬럼의 실제 값 목록('완료' | '취소' | ...)과 값 범위를 함께
    제공합니다. "긴급 티켓"이 priority='긴급'임을 모델이 추측할 필요가 없어집니다.
 3) 평가 루프 — 프롬프트 수정이 개선인지 퇴행인지 숫자로 확인되지 않으면 개선이 아니라
    도박입니다. 골든셋 질문은 few-shot 예제와 겹치지 않게 구성해 정보 누출을 막았습니다.

3. 사용된 핵심 기술 / 프레임워크
━━━━━━━━━━━━━━━━━━━━━━━━━━━

 • LLM — OpenAI GPT (Chat Completions API, reasoning_effort로 추론 깊이 조절)
   Anthropic Claude도 동일 인터페이스로 지원하며 API 키 접두어로 공급자를 자동 판별합니다.
   공급자 코드는 src/llm.py 한 파일에 격리했습니다.
 • SQL 안전성 — sqlglot: AST 파싱, 금지 노드 탐지, LIMIT 주입, 방언 정규화
 • 데이터 — SQLite 읽기 전용 커넥션 + 합성 데이터셋 생성기 (9테이블 24,366행)
 • 웹 UI — Streamlit (chat_input, status, tabs, 스트리밍 출력)
 • 시각화 — Plotly Express (결과 모양에 따른 차트 자동 선택)
 • ERD — Graphviz DOT 자동 생성. st.graphviz_chart가 브라우저에서 렌더링하므로
   시스템 패키지 설치가 필요 없습니다 (배포 실패 지점을 늘리지 않는 선택)
 • 평가 — 자체 골든셋 + Execution Accuracy 채점기 (컬럼명·행 순서 무시, 수치 반올림 비교)
 • 비용 최적화 — 프롬프트 캐싱: 매 요청 동일한 규칙·세만틱 레이어를 프롬프트 앞쪽에
   고정 배치해 캐시 프리픽스를 유지. 사이드바에서 캐시 적중 토큰을 실시간 확인
 • 관측성 — 단계별 실행 추적, 토큰·비용·지연시간 계측

의존성은 6개로 최소화해 배포 실패 지점을 줄였습니다.

4. 보안 및 개인정보 처리
━━━━━━━━━━━━━━━━━━━━━━━━━━━

 • API 키는 Streamlit Secrets로만 주입되며 코드·저장소·화면 어디에도 노출되지 않습니다.
 • 읽기 전용 2중 방어 — sqlglot AST 정적 검증 + SQLite mode=ro 커넥션
 • 차단 대상 — INSERT/UPDATE/DELETE/DROP/ALTER/CREATE/PRAGMA/ATTACH,
   세미콜론 다중 문장, sqlite_master, load_extension, 존재하지 않는 테이블,
   민감 컬럼(employees.annual_salary)
 • 자원 상한 — 결과 행 제한, 쿼리 타임아웃, 자기수정 횟수 상한
 • 데이터 — 전부 seed 고정 난수로 생성한 가상 데이터입니다. 사내 기밀·개인정보가
   일절 포함되지 않으며, seed가 고정되어 배포 환경마다 동일하게 재현됩니다.

5. 실제 DB로 이어가기 위한 설계
━━━━━━━━━━━━━━━━━━━━━━━━━━━

이 PoC는 데모로 끝나지 않도록 교체 지점을 한 곳에 모아 두었습니다.

 • LLM 공급자 교체 → src/llm.py 한 파일
 • 실제 사내 DB 연결 → src/db.py의 get_connection() / introspect() 두 함수뿐
   (가드레일·스키마 링킹·평가·UI는 그대로 재사용)
 • 스키마 링킹 고도화(임베딩 검색 + 리랭커) → schema_linker.link() 인터페이스 유지
 • 다음 단계 — 예제 뱅크 벡터 DB 영속화, 사용자 권한(RLS/CLS) 연동,
   골든셋 200~500문항 확장 후 CI 회귀 테스트, 질의 로그 기반 대시보드 자동 추천
